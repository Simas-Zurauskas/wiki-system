# Existing output: ownership and replacement

`init` creates a fresh source-backed map. Previous generated pages are replaceable output, not a
layout to migrate or a compatibility contract. An unsupported old map encountered during `update`
uses this same fresh-writing procedure at the resolved destination and repo scope. Installing a
skill release never rewrites project wikis by itself.

## Protect owner material before replacement

Read existing state/plan declarations and file headers only as needed to identify generated ownership,
recorded repos, policy pointers and preservation blocks. Do not infer ownership from a directory name,
reuse old prose as source evidence, or require an old-to-new topic inventory or migration plan.
Keep handwritten files, task history, notes, product specs, rules, LINKS, task prompt and entry
instructions unchanged. Preserve complete keep/AUTOREGEN_SKIP blocks byte-for-byte in their parent
page; regenerate useful surrounding content there rather than turning the page into a redirect.
An uncertain file remains owner-owned and is reported, not deleted or silently claimed.

Before edits, keep a temporary restorable copy of replaceable output/state outside the active wiki.
Preserve dirty bytes too. No in-wiki archive, migration ledger or old-skill backup is required.

## Capture real source, then write new output

Set up schema-3 planning state with explicit managed ownership before source capture. For confirmed
legacy generated files, normalize their generated header to the current marker before capture,
preserving all other bytes at that point; declare their paths alongside planned new pages. This lets
snapshot preservation distinguish replaceable output from handwritten files. Never relabel owner
content to bypass preservation. Retain valid existing schema-3 repo baselines until finalization;
for unsupported legacy state, do not transplant its timestamps/fingerprints as new verification.

Use init's capture, source-writing, bounded review and finalization steps. Select navigation units
from current source workflows, not previous filenames. Delete superseded confirmed generated pages
and generated old machinery within the requested docs destination; retain owner material and any
unavailable repo's last-known pages/snapshot, reporting partial availability. Do not fake source
metadata or advance a baseline after a failed run.

## Links and completion

Generated pages/signposts written in this run link directly to current destinations. Incoming links
from untouched source READMEs, customized task prompts, entry files or history do not authorize
compatibility pointers, redirects, placeholder pages or reconstruction of the old tree. Report those
remaining links concisely; they do not block a fresh map. Change owner files only when authorized;
`context` can connect entry instructions separately.

Preserving old URLs/paths, migrating documentation history or creating archives happens only when
the user explicitly requests that outcome; `init` alone is not such a request. After successful
review and checks, remove the temporary backup unless the user requested retention. Never run the
old generator against the new map.
