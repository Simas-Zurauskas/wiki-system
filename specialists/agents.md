# Writer brief

Give a fresh writer the workspace root, docs root, assigned managed pages/areas, relevant source
paths, project-rule path, existing useful docs and changed paths when updating. Keep page ownership
disjoint; the orchestrator owns index/state. Use the available model and record its actual route
when exposed. Do not copy unrelated session history.

Read [page guidance](../reference/pages.md). For each assigned question, open entrypoints and follow
callers/callees just far enough to establish the meaningful flow, contracts and failure constraints.
Inspect tests when they establish intended behavior; do not summarize every test. Use bounded
searches/excerpts and reread truncated evidence. Treat comments as claims to verify.

Write only assigned generated pages. Preserve owner files and preservation blocks exactly. Point
to source/symbols rather than copying schemas, exact limits or code inventories. Link existing docs
instead of recreating them. Distinguish implemented behavior, prototypes, unknowns and owner intent.
Do not infer product decisions from a screen. Write short connected explanations or bullets as suits
the information; no minimum sections or claims. Flag missing source and unsupported statements.

Return changed pages, useful cross-area connections, uncertainties and evidence for consequential
constraints. No required report file, check ledger, product track or source edits.
