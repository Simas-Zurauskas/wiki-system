# Bounded source review

Structural checks establish valid state/links, not true claims. The writer opens the source behind
changed behavior. This review separately challenges the consequential parts of that account.

For init, review contracts and consequential constraints plus one ordinary area or index section.
For updates, prioritize changed contracts/constraints and rotate an ordinary area; use the previous
review summary so the same easy page is not always sampled. Full update requires rereading every
area's relevant flows by writers; independent verification may still be a disclosed bounded sample.

A small run can be self-reviewed. For substantial work use one fresh independent batch reviewer
where available and permitted, with requirements, owner rules, raw source and selected pages—not
an instruction to endorse the writer's conclusions. Batch by actual risk, not one verifier per page.
Disclose self-review; do not invent model diversity, usage or coverage.

Trace callers, boundary validation, consumers and relevant tests. Attempt to refute suspected errors
before reporting. Separate wrong claims, missing consequential connections and unresolved questions.
A valid path, large file or missing preferred tool is not a factual finding. Don't manufacture product
requirements or insist that navigation prose reproduce every branch. Recheck supported corrections;
stop with partial status when evidence is unavailable rather than enter an unlimited repair loop.

Record `review_summary` in state: managed pages/sections actually reviewed, the ordinary area's id
(or null for an index-only map), method (`self` or `independent`) and remaining limitations. No per-rule
receipts or report tree. Preserve unresolved limitations on subsequent no-op runs. Source stability
finalization is separate from this semantic judgment and never proves it happened automatically.
