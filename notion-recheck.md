Your task is to audit the **published Notion content against the source code**
and correct drift. The ground truth is the source code — the same ground truth
the local `recheck.md` uses. The audited *subject* is what is actually in Notion
(fetched live), NOT the local wiki: local is not assumed correct here.

This prompt is the **Notion recheck orchestrator** (`/wiki-system notion recheck`).
It is the Notion analog of `recheck.md`: where `recheck.md` verifies the **local
wiki against the source code**, this verifies the **live Notion pages against the
source code**. It is **not** a re-sync — it does not re-render local and push.

It composes three existing contracts and does not redefine them:
- `specialists/verifier.md` — the per-page accuracy check (Notion content vs `scope_files`).
- `specialists/technical.md` / `specialists/product.md` — regenerate a drifted page from code.
- `notion.md` — render + push (N3.1, child-preservation), structure, orphans (N4), the mapping.

It reads `wiki/.internal/plan.yaml` for each page's `scope_files`, and the mapping
(`spec/notion-sync-schema.md`) to connect a Notion page → its disk node → its `scope_files`.

## WHAT THIS IS, AND WHEN TO USE IT

| Situation | Use this | Use something else |
| --- | --- | --- |
| "Is what's *published in Notion* still accurate against the code?" | ✅ this prompt | |
| "Someone edited pages in Notion — are those edits correct, and fix them if not" | ✅ this prompt | |
| "Code changed; make sure the Notion docs reflect it" | ✅ this prompt | |
| "I edited local pages; just push them" | | `notion sync` (push, no audit) |
| "Audit the *local* wiki vs code" | | `recheck.md` |

**Three commands, three jobs:**
- **`notion sync`** (`notion.md`) — push disk → Notion, trusting local hashes.
  Never looks at the Notion side or the code.
- **`recheck`** (`recheck.md`) — verify the **local** wiki against the code; fix local.
- **`notion recheck`** (this) — verify the **live Notion** content against the
  code; fix the pages that drifted. Catches drift in the *published artifact*
  that neither of the others sees: code that changed since publish, a human who
  edited a Notion page, or local content that was synced while already stale.

## KEY PRINCIPLES (read before auditing)

- **Ground truth is the source code.** Not local, not Notion. Every verifiable
  page is checked against its `scope_files`, exactly as `recheck.md` does — the
  difference is only *which copy of the prose* gets checked: the live Notion page,
  not the local file.
- **The audited subject is the live Notion content.** Fetch it and verify it.
  Do not assume the local file is correct and do not just re-push it.
- **Fixes are regenerated from code and land in BOTH places.** A page that fails
  verification is regenerated by its writer from `scope_files`, written to its
  local `wiki/library/` file, **and** pushed to Notion. Fixing both keeps the
  source and the mirror code-accurate and consistent, and stops the next
  `notion sync` from clobbering the fix. This command therefore *does* write local
  reference files (only the regenerated corrections) — unlike `notion sync`, which
  is read-only on `wiki/`. (One lag: the corrected page's *local* verifier report,
  `wiki/.internal/verification/<id>.yaml`, is not refreshed here — the content is
  code-accurate, but that local report stays stale until the next local `recheck`.)
- **Derived pages have no code to check.** The root page body (`wiki/OVERVIEW.md`),
  the `Topics` page (`wiki/topics.md`), and the `Library` container's overview
  are orchestrator-*synthesized* — they have no `scope_files`. For these, the
  canonical source is the local synthesized file, so they are reconciled to local
  (re-push if Notion drifted). This is the only place local is the reference, and
  only because there is no code to verify against.
- **`Notes` is human-owned.** Never audited, never overwritten; recreated only
  if a human deleted it.
- **Nothing destructive happens silently.** Orphan archiving asks (per `notion.md`
  N4). Foreign pages (a human added, never ours) are left untouched and reported.

## ROLE

You are an audit-and-correct orchestrator. Your job, in order:

1. Preflight; resolve the root page and the mapping (rebuild from Notion if stale); load the plan.
2. Walk Notion, match pages to disk nodes + plan pages, classify them.
3. Verify each verifiable page's **live Notion content** against its `scope_files`.
4. Correct drift: regenerate failing pages from code into both local and Notion (bounded retry).
5. Reconcile structure (missing / orphan / dead / foreign / moved / renamed); `Notes` untouched.
6. Finalize: update the mapping and write the audit report.

You write `wiki/.internal/notion-sync.yaml`, `wiki/.internal/notion-recheck-report.md`,
the per-page verifier reports, and — for corrected pages only — their
`wiki/library/*.md` files. You never touch `wiki/notes/` or publish `wiki/.internal/`.

## PHASE NR0: PREFLIGHT, ROOT & INPUTS

Sequential. (MCP gate + markdown spec first, per § HARD DEPENDENCY.)

1. **CWD sanity** — `wiki/library/` exists in CWD. Else halt.
2. **Load the plan** — read `wiki/.internal/plan.yaml`. It supplies each page's
   `owner_agent` and `scope_files`, which this audit requires. If it is absent or
   invalid, **halt**: without `scope_files` there is no code to verify against —
   tell the user to run `init`/`recheck` first.
3. **Resolve the root page** — `meta.root_page_id` from `notion-sync.yaml` if
   present; else a passed argument; else ask, or `notion-search` by title and
   confirm. `notion-fetch` it to confirm access.
4. **Load the mapping as a cache** — if `notion-sync.yaml` exists, validate it; if
   absent or invalid, that is NOT fatal — NR1 rebuilds it from Notion's structure.
   Record whether the run is a full re-establish. Note `meta.generator_version`: if
   it differs from the current generator (skill version + model id), the mirror was
   published by an older skill/model — audit **all** pages this run rather than
   skipping unchanged ones (NR2.1), since a generator change can shift what counts
   as a defect. Note the generator change in the report.

---

## PHASE NR1: WALK NOTION, MATCH, CLASSIFY

### NR1.1 Walk the live Notion tree
From the root, `notion-fetch` and recurse through child pages, building the live
tree (id, title, parent, position).

### NR1.2 Match Notion pages to disk nodes + plan pages
Match each live Notion page to a disk node — by cached `notion_page_id` first,
then by tree position + title (this is what makes the mapping rebuildable from
Notion alone). Through the disk node, look up the plan page to get its
`owner_agent` and `scope_files`. Rebuild the authoritative mapping from these
matches.

### NR1.3 Classify each page

| Class | Pages | Handling |
| --- | --- | --- |
| **verifiable** | reference leaf/folder pages that have `scope_files` in the plan | Audited vs code (NR2–NR3). |
| **derived** | the root body (`wiki/OVERVIEW.md`), the `Topics` page (`wiki/topics.md`), the `Library` overview — orchestrator-synthesized, **no `scope_files`** | Reconciled to the local synthesized file (NR3.3); not code-verified. |
| **working** | the `Notes` page | Skipped entirely (human-owned). |
| **structural** | `missing_in_notion` / `dead_id` / `orphan_in_notion` / `foreign` / `moved` / `renamed` | Reconciled in NR4. |

---

## PHASE NR2: AUDIT NOTION CONTENT AGAINST CODE (verify-first)

Parallel. This is the core — the Notion analog of `recheck.md` Phase R3, but the
draft under test is the **live Notion page**, not the local file.

### NR2.1 Skip what cannot have drifted
A verifiable page needs re-verification only if its **Notion content** changed
(its live serialization hash ≠ stored `notion_content_hash`) **or** its **code**
changed (any `scope_files` changed since `meta.synced_at`, via `git diff`). If
both are unchanged, skip it (record "unchanged") — same economy as `recheck.md`'s
`state: unchanged`. On a rebuilt mapping with no baselines, verify everything.

### NR2.2 Verify each remaining page
For each page to audit:
1. `notion-fetch` its live content and write it to a scratch draft at
   `wiki/.internal/notion-recheck/<page-id>.fetched.md`. **Note:** this draft is
   Notion-flavored markdown — it contains `<page>` / `<mention-page>` / `<table>`
   blocks, not plain wiki links. The verifier extracts factual claims from the
   prose and ignores those navigation wrappers, so it runs unchanged; just be
   aware it is verifying Notion's serialization, not the local file.
2. Dispatch a verifier (`specialists/verifier.md`, mode from `owner_agent`) with
   `page_path` = that scratch draft and `scope_files` from the plan. Use the
   verifier brief template from `init.md` § SUB-AGENT DELEGATION PRINCIPLES; write
   the report to `wiki/.internal/verification/<page-id>.notion.yaml` (the `.notion`
   suffix keeps it distinct from local-recheck reports).
3. Collect the verdict (`pass` / `fail_soft` / `fail_hard`).

Verifiers are read-only and parallel — use the worker-pool cap from `init.md`
§ SCALING RULES.

---

## PHASE NR3: CORRECT DRIFT (regenerate from code → local + Notion)

### NR3.1 Regenerate failing pages
For each `fail_soft`/`fail_hard` page, dispatch the page's writer
(`specialists/technical.md` or `product.md`, per `owner_agent`) to **regenerate it
from `scope_files`** — attach the verifier's `issues` list (the auto-fix
re-dispatch protocol from `init.md` Phase 3d). The writer produces corrected
markdown the same way local generation does. (Bounded: **one** regenerate→re-verify
retry per page, identical to `recheck.md` R4.3. A still-failing page is recorded
`fail_hard` in `_failures.md` and left as-is in Notion — do not ship content the
verifier rejects.)

### NR3.2 Write the fix to both places
A page that now passes is written to **both**:
- its local file `wiki/library/<…>.md` (the writer's normal output), and
- Notion — render it via `notion.md` N3.1 (resolve cross-links, append child
  `<page>` refs) and `replace_content` with `allow_deleting_content` off
  (child-preservation).

Then refresh `content_hash` and capture `notion_content_hash` (hash of Notion's
serialization after the push) so the next audit can skip it.

### NR3.3 Derived pages
Root body / `Topics` / `Library` overview have no `scope_files`, so they are not
code-verified. Their canonical source is the local synthesized file
(`wiki/OVERVIEW.md`, `wiki/topics.md`, `wiki/library/OVERVIEW.md`). If the live
Notion content differs from that local file's rendering, re-push the local file;
otherwise leave it. (If the local synthesized files themselves are stale, that is
a job for `recheck.md`'s finalize, not this command.)

## PHASE NR4: STRUCTURAL RECONCILIATION

Independent of content. Apply per class from NR1.3:

| Class | Action |
| --- | --- |
| `missing_in_notion` / `dead_id` | Recreate from local under the correct parent (top-down, `notion.md` N2). |
| `orphan_in_notion` | Mapped page whose disk node is gone → surface and **ask** (archive / leave / rename), per `notion.md` N4. |
| `foreign` | A human-added page that was never ours → **leave untouched**, report. |
| `moved` | Notion parent ≠ disk parent → move back (`notion-move-pages`), report. |
| `renamed` | Notion title ≠ node H1 → reset title (`update_properties`), report. |
| `working` | Untouched. Recreate with the placeholder only if it is missing. |

Persist the mapping incrementally (resumability).

## PHASE NR5: FINALIZE

1. **Persist the mapping** — `wiki/.internal/notion-sync.yaml`, valid against
   `spec/notion-sync-schema.md`, with refreshed `content_hash` /
   `notion_content_hash` per audited page and `meta.synced_at`.
2. **Write the report** — `wiki/.internal/notion-recheck-report.md`:

```markdown
# Notion recheck (audit vs source code) — <ISO timestamp>

Root page: <url>
Mapping: loaded-from-cache | rebuilt-from-Notion

## Audit
- Verified: <n>   Skipped (unchanged): <n>
- Drifted from code → fixed (local + Notion): <n>
- Still failing after one retry (fail_hard, left as-is): <n>

## Pages corrected (regenerated from code)
| Page | Verdict | What drifted (top issue) |
| --- | --- | --- |
...

## Structure
- Recreated (missing/dead): <n>   Moved: <n>   Renamed: <n>
- Orphans: <n> (archived / left / renamed)   Foreign left: <n>

## Flags
- Derived pages re-pushed to match local: ...
- fail_hard pages needing human review: ...
```

3. **Summarize** — counts, root URL, what was corrected (and that the fix landed
   in both local and Notion), what's still failing, and whether the mapping was
   rebuilt. Tight.

## EDGE CASES

- **A human edit that is actually correct** — verifies `pass` against code → left
  in place (its wording may differ from local; that's fine, both are accurate).
  Only *inaccurate* content is regenerated.
- **A human edit that is wrong** — fails against code → regenerated from code,
  fixed in Notion + local. The human's incorrect text is discarded; report it.
- **Code changed since publish** — the Notion page now contradicts the code →
  fails → regenerated. This is the main steady-state case.
- **Fix would be clobbered by sync** — prevented: NR3.2 writes the regenerated
  content to local too, so local == Notion == code-accurate and `content_hash`
  matches; a later `notion sync` sees local unchanged and does nothing.
- **Lost / fresh-checkout mapping** — NR0 resolves the root; NR1 rebuilds the
  mapping from Notion's structure. Report it as a full re-establish.
- **No `scope_files` (derived page)** — not code-verified; reconciled to the local
  synthesized file (NR3.3).
- **`plan.yaml` missing** — halt (no code scope to verify against); run `init`/`recheck` first.
- **Page deleted/moved/renamed in Notion** — structural (NR4), independent of the
  content audit.
- **Serialization noise** — never byte-compare; the content check is the verifier
  (claims vs code), and the skip check is `notion_content_hash` (Notion's own
  serialization) — never a diff of fetched-markdown vs sent-markdown.

## QUALITY GATES

- [ ] **Audited against code, not local.** Every verifiable page's verdict came
      from a verifier run over the **live Notion content** + its `scope_files` —
      not from a local-vs-Notion diff.
- [ ] **Fixes in both places.** Every page corrected this run was written to its
      local `wiki/library/` file AND pushed to Notion, with matching hashes.
- [ ] **No shipped failures.** No page left in Notion with a `fail_hard` verdict
      from a regeneration that didn't pass; such pages are in `_failures.md`.
- [ ] **`Notes` untouched; foreign untouched.** Neither was audited, moved,
      renamed, or overwritten.
- [ ] **Child preservation.** No root/folder push dropped a child sub-page.
- [ ] **Mapping authoritative.** Rebuilt from Notion where the cache was stale;
      every live managed page maps to one disk node or an explicit orphan/foreign entry.
- [ ] **`wiki/notes/` and `wiki/.internal/` content untouched** (the latter is
      read, never published).

---

## CONSTRAINTS

- **Ground truth is the source code.** This command verifies Notion content
  against `scope_files`; it does not treat local as correct, and it is not a re-sync.
- **Fixes regenerate from code and update both local and Notion.** It writes
  `wiki/library/*.md` for corrected pages — the only files under `wiki/` it writes.
- **Bounded retry.** One regenerate→re-verify per page (identical to `recheck.md`).
- **`Notes` and foreign pages are sacrosanct.** Never audited or overwritten;
  orphans only ever archived with explicit confirmation.
- **MCP-only Notion access**; **markdown spec is authoritative** for Notion syntax.
